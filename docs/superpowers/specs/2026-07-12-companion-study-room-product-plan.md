# “陪伴自习室”多端 App 整体规划

> 版本：1.0｜日期：2026-07-12｜目标市场：中国大陆｜MVP：Web + 微信小程序

## 1. 执行摘要

产品面向大学生、考研考证者和成人学习者，解决独自在家学习时的孤独、拖延与缺少监督问题。核心不是再做一个番茄钟，而是把“环境陪伴、AI 陪伴、好友共学、目标复盘”组成闭环。

建议由 1–3 人团队用 8–12 周完成 MVP：业务系统自研，实时音视频、大模型、对象存储和内容审核采用国内云服务。首期同时验证单人和多人两条路径，但资源约按 60% 投入单人体验、40% 投入好友共学。不要在 MVP 做陌生人匹配、公开广场、大型房间、摄像头专注识别、复杂桌宠养成或第三方学习平台同步。

项目技术可行，整体为“中高难度”。最大风险不是白噪音或 AI 问答，而是微信小程序音视频限制、多人视频成本、社交内容治理、冷启动以及用户付费意愿。学习进度跟踪并不难：第一版采用用户可解释的“设定目标—记录过程—结束确认—周报复盘”，不声称自动判断知识掌握程度。

## 2. 已确认的产品约束

- 首发：中国大陆。
- 首批用户：大学生、考研考证及成人学习者。
- 年龄：原设想为 16+；但 16–17 岁仍属于未成年人。商业上线建议优先改为 18+。如坚持 16+，必须为未成年人配置更严格的隐私、视频、举报和监护规则。
- 终端：先做响应式 Web 和微信小程序，验证后再做 iOS、Android 或桌面端。
- 团队与周期：1–3 人，8–12 周。
- 产品策略：单人和多人均进入 MVP，单人优先；仅支持好友邀请，不做陌生人匹配。
- 进度跟踪：开始前填写目标，结束后由用户确认完成度，AI 根据目标、时长和问答生成总结。

## 3. 用户问题与价值主张

### 3.1 主要用户任务

1. 我想迅速进入一个有学习氛围、但不打扰我的环境。
2. 我需要一个温和的外部约束，帮助我开始并坚持。
3. 我想和认识的人一起学习，但不想组织复杂的视频会议。
4. 学习结束后，我想知道今天做了什么、目标完成得怎样、下一步是什么。

### 3.2 差异化定位

竞品通常只覆盖一个切面：Forest 强在游戏化专注，潮汐/LifeAt 强在氛围，Focusmate/StudyStream 强在真人共学，StudyFetch 强在 AI 学习工具。本项目的机会是把四者连接起来，但必须保持克制：AI 伙伴服务于“开始、坚持、复盘”，不能演变成无边界聊天机器人；好友视频服务于强关系监督，不能在 MVP 演变成陌生人社交平台。

## 4. MVP 用户流程与功能边界

### 4.1 核心流程

1. 微信登录，设置昵称、头像、城市、学习方向；性别和城市默认不公开，可由用户选择展示。
2. 选择“独自自习”或“邀请好友”。
3. 填写本次目标、预计时长，选择图书馆、森林、海边、咖啡厅或雨天场景。
4. 进入自习：动态场景、白噪音、计时器、AI 桌宠状态同时运行。
5. AI 支持主动问答，并仅在约定节点轻量提醒：开始、长时间暂停、休息点和结束前；禁止频繁打断。
6. 多人房间支持 2–4 人，通过微信卡片或链接邀请；提供摄像头、麦克风、文字状态和退出按钮。
7. 结束时用户确认完成度（0–100%）、实际完成内容和未完成原因。
8. 系统生成本次摘要：有效时长、目标完成度、共同学习者、暂停次数、问答主题与下一步建议。
9. 记录进入学习日历、连续天数和周报，并支持一键再次邀请。

### 4.2 MVP 必须包含

- 微信授权登录与账号合并预留。
- 个人资料、好友申请/接受/删除、隐私开关。
- 单人房间、2–4 人好友私密房间、邀请链接失效机制。
- 五个有合法授权的白噪音与场景主题。
- 正计时或倒计时、暂停、提前结束、断线恢复。
- AI 文本问答、受控提醒、会话摘要；AI 输出明确标识。
- 目标、结束复盘、历史记录、周统计。
- 视频开关、默认静音、基础弱网降级、房间异常恢复。
- 举报、拉黑、房间踢出、敏感文本审核、运营后台最小闭环。
- 埋点、错误监控、费用告警和 AI/音视频用量限额。

### 4.3 明确不做

- 陌生人匹配、公开房间和学习广场。
- 4 人以上会议、直播、回放或云端录像。
- 摄像头画面分析、表情/视线识别或“专注分”。
- 第三方网课、Notion、学校教务系统同步。
- AI 自动认定用户是否真正掌握知识。
- 桌宠养成、装扮商城和复杂虚拟货币。
- 付费课程、老师市场和家长端。

## 5. 学习进度与 AI 伙伴设计

### 5.1 可落地的进度模型

进度跟踪拆成三层，避免把“在线时长”等同于“学习效果”。

| 层级 | MVP 数据 | 能回答的问题 | 可信度 |
|---|---|---|---|
| 行为进度 | 开始/结束时间、暂停、房间人数 | 学了多久、是否按时开始 | 高 |
| 任务进度 | 用户目标、结束确认、未完成原因 | 计划完成了多少 | 中高，依赖自报 |
| 知识进度 | AI 问答主题、用户自评 | 学了哪些主题、卡在哪里 | 中；不能代表掌握 |

每次会话保存 `计划目标、预计分钟、实际有效分钟、完成度、复盘文本、AI 主题标签`。周报计算计划完成率、总有效时长、最常学习主题、常见未完成原因，并由 AI 生成下一周建议。后续再加入可选的测验、资料上传或第三方同步，以提高知识进度可信度。

### 5.2 AI 伙伴的职责边界

- 做：澄清目标、回答学习问题、提示休息、总结问答、帮助复盘。
- 不做：持续监听麦克风、读取视频、诊断心理或健康问题、替用户完成考试作业、以情感依赖促进留存。
- 桌宠只是 AI 状态的视觉映射：待机、专注、思考、鼓励、休息五种状态；MVP 使用 Lottie/Rive 动画，不需要 3D 引擎。
- 所有自动发言由规则引擎触发，大模型只生成内容。用户可关闭主动提醒、删除单次会话和关闭历史个性化。
- AI 回答采用“短回答优先”，限制上下文和输出长度；复杂问题提示用户开启一次深入问答，以控制费用和打扰。

## 6. 技术路线与架构

### 6.1 推荐架构

采用模块化单体和托管云能力，不采用微服务。

```text
微信小程序 ─┐
             ├─ HTTPS / WebSocket ─ API 网关 ─ 模块化业务服务 ─ PostgreSQL
响应式 Web ─┘                         │             ├─ Redis
      │                               │             ├─ 对象存储/CDN
      ├─ 场景动画 + 本地/流式白噪音    │             └─ 任务队列
      └─ TRTC 音视频 SDK ─────────────┤
                                      ├─ AI 供应商适配层 ─ 国内已备案模型
                                      ├─ 内容审核服务
                                      └─ 埋点、日志、告警
```

### 6.2 建议技术栈

| 领域 | 建议 | 理由 |
|---|---|---|
| Web | Next.js + React + TypeScript | 桌面体验、SEO 落地页、生态成熟 |
| 小程序 | Taro + React，房间页允许使用微信原生组件 | 共享类型和部分业务逻辑，同时保留音视频底层控制 |
| 代码组织 | pnpm monorepo + Turborepo | 共享 API SDK、类型、埋点和设计令牌，不强求 UI 全复用 |
| 服务端 | NestJS + TypeScript，模块化单体 | 小团队上手快，与前端共享类型，后续可按模块拆分 |
| 数据 | PostgreSQL + Redis | 事务数据、好友关系、房间临时态和限流 |
| 实时音视频 | 腾讯云 TRTC，封装 `RtcProvider` 接口 | Web、小程序及未来 App 覆盖完整；避免自建 WebRTC SFU |
| AI | `AiProvider` 适配层接国内已备案模型 | 可在价格、质量、备案与可用性之间切换 |
| 动画 | Lottie 或 Rive | 五状态桌宠足够，资源和开发成本低 |
| 文件 | COS + CDN | 场景资源、白噪音、头像和导出周报 |
| 可观测性 | Sentry 类错误监控 + 云日志 + 自建业务看板 | 快速定位弱网、浏览器和供应商问题 |

腾讯云公开资料显示 TRTC 覆盖 Web、微信小程序、React Native、Flutter 和原生端，适合作为后续多端扩展的统一音视频层；其计费页截至调研日列出入门版按量计费，以及 625 元/月含 11 万分钟等套餐。需要注意，某些小程序增强能力或低代码组件要求更高套餐，正式采购前必须用真实 Demo 验证类目和套餐限制。[腾讯云 TRTC 产品页](https://cloud.tencent.com/product/trtc?Is=home)｜[TRTC 定价](https://buy.cloud.tencent.com/price/trtc)

### 6.3 核心模块

- 身份与隐私：微信身份、用户资料、年龄声明、展示字段权限、注销和数据导出。
- 社交关系：好友申请、接受、删除、拉黑；不实现关注/粉丝模型。
- 学习会话：目标、计时状态机、暂停、恢复、完成和统计。
- 房间：邀请令牌、成员、角色、心跳、重连和过期清理。
- RTC 适配：令牌签发、设备检查、质量事件、音视频开关和供应商错误映射。
- AI 编排：提示词版本、触发规则、上下文裁剪、限额、审核、摘要和供应商降级。
- 内容与场景：主题配置、音频授权、资源版本和缓存。
- 安全运营：举报、封禁、审核队列、审计日志和紧急开关。
- 分析计费：漏斗事件、留存、供应商用量、用户级成本和预算告警。

### 6.4 关键数据流与容错

- 计时以服务端会话时间为准，客户端每 15–30 秒心跳；短时断网本地继续显示，重连后按规则校正。
- RTC 令牌由服务端短时签发，不在客户端保存密钥。弱网时依次降低分辨率、关闭远端视频并保留文字状态。
- 白噪音在客户端播放，不混入 RTC 上行音轨，避免回声和音视频费用增加。
- AI 请求先过输入审核和额度检查，再调用模型；超时后返回固定提示，不阻塞计时。总结任务异步执行，失败可重试。
- 不录制视频、不保存摄像头截图。只保存必要的房间质量指标和举报证据；如未来引入截图审核，必须重新征得同意并更新隐私政策。

## 7. 实现难度评估

| 模块 | 难度 | 主要难点 | MVP 策略 |
|---|---:|---|---|
| 账号、资料、好友 | 中 | 微信登录、隐私字段、拉黑关系 | 使用成熟登录流程，资料最小化 |
| 目标、计时、统计 | 中 | 多端状态一致、断线校正 | 服务端状态机 + 客户端缓存 |
| 白噪音与场景 | 低–中 | 音频授权、自动播放限制、包体积 | CDN/分包、首期五套资源 |
| AI 问答与总结 | 中 | 费用、幻觉、安全、上下文 | 短上下文、限额、异步总结 |
| AI 桌宠 | 中 | 动画状态同步、跨端性能 | 2D 五状态，不做养成 |
| 2–4 人视频 | 高 | 小程序类目、设备权限、弱网、成本 | 使用 TRTC，不录像，默认标清 |
| 内容治理与后台 | 高 | 视频无法仅靠文本审核、举报响应 | 私密好友房、拉黑举报、人工处置 |
| 多端一致性 | 中–高 | Web/小程序音视频和音频差异 | 共享领域层，房间 UI 分端实现 |
| 自动判断学习掌握 | 很高且不可靠 | 缺少可信数据源 | MVP 明确不做 |

### 8.2 市场结论

1. 需求已被多个相邻品类验证，但“全功能集合”本身不是壁垒。
2. 真人共学的价值最直观，却也是成本与安全风险最高的模块；好友私密房是合理切入口。
3. 氛围内容适合提升首次体验和传播，但容易被复制，必须与目标/复盘数据形成长期价值。
4. AI 学习工具竞争激烈。真正差异应是 AI 了解本次目标与历史节奏、在正确时刻出现，而不是通用问答能力。
5. 公开自习社区需要规模才有“随时有人”的价值。小团队不应在早期挑战双边冷启动。
6. 线下付费自习室报告曾给出 2022 年中国用户规模 755 万、预计 2025 年超过千万的量级，说明付费学习环境存在需求，但线下消费不能直接推导线上订阅意愿。[公开报道所引行业报告](https://e.chinacqsb.com/attachment/202412/20/73227275-43a8-45a1-8298-99c62cca79be.pdf)

## 9. 商业模式建议

### 9.1 收益渠道优先级

1. **个人订阅（首选）**：免费版提供单人基础场景、有限 AI 次数和有限多人视频时长；Pro 提供更多场景、周报、更多 AI 额度和多人时长。建议验证价为 18 元/月、128 元/年，而非一开始追求高价。
2. **低成本虚拟内容（第二阶段）**：主题场景、声音包、桌宠皮肤，一次性 6–18 元；必须避免影响专注的抽卡和强付费诱导。
3. **学习小组/校园版（验证后）**：固定小组、组长统计、批量权益，可向考研社群、培训机构或企业学习社群收费。
4. **品牌合作（规模后）**：文具、图书、考试服务的主题场景或联名活动；不能在自习过程中插入打断式广告。
5. **不建议首期广告**：学生用户价值低、破坏沉浸感，也增加隐私与内容合规负担。

### 9.2 免费与付费边界

| 能力 | 免费 | Pro 建议 |
|---|---|---|
| 单人自习 | 不限基础计时 | 高级统计、跨设备历史 |
| 场景 | 2 个常驻 + 轮换 | 全部场景与声音包 |
| AI | 每日 3 次短问答、基础总结 | 更高额度、周报、个性化建议 |
| 多人视频 | 每周 3 场或每月固定分钟 | 更高额度；仍设公平使用上限 |
| 复盘 | 单次记录、近 7 天 | 完整历史、周/月趋势和导出 |

## 10. 成本评估

### 10.1 研发与上线一次性成本

以下为人民币规划区间，不是供应商报价。创始人自研时现金支出更低，但仍应把机会成本计入经济模型。

| 项目 | 极简自研 | 小团队市场成本 | 说明 |
|---|---:|---:|---|
| 2–3 名研发，8–12 周 | 6–18 万 | 18–45 万 | 全栈、小程序/前端、兼职设计测试 |
| UI、插画、五套场景与声音授权 | 1–4 万 | 3–10 万 | 原创质量和版权范围决定差异 |
| 法务、隐私文本、主体/备案/软件材料 | 0.5–2 万 | 2–6 万 | 不含特殊资质或长期顾问 |
| 测试设备、域名、证书、工具 | 0.5–1.5 万 | 1–3 万 | 覆盖主流微信与浏览器 |
| 上线前种子运营 | 1–3 万 | 3–10 万 | 校园社群、内容和用户访谈 |
| **合计** | **9–28.5 万** | **27–74 万** | 建议准备 15% 风险缓冲 |

### 10.2 月度运营成本

| 成本项 | 内测/1 万 MAU | 5 万 MAU | 20 万 MAU | 主要驱动因素 |
|---|---:|---:|---:|---|
| 基础云、数据库、CDN、监控 | 1,000–4,000 | 4,000–12,000 | 12,000–35,000 | 峰值、日志、资源体积 |
| AI 调用与审核 | 500–3,000 | 4,000–15,000 | 20,000–70,000 | AI 使用率、上下文、模型 |
| RTC 音视频 | 1,000–6,000 | 8,000–30,000 | 40,000–150,000 | 多人占比、时长、分辨率 |
| 客服、审核、运营 | 5,000–15,000 | 15,000–40,000 | 40,000–100,000 | 举报量、活动与社群 |
| 内容与持续研发 | 10,000–30,000 | 20,000–60,000 | 40,000–120,000 | 团队是否全职计薪 |
| **月度合计** | **1.75–5.8 万** | **5.1–15.7 万** | **15.2–47.5 万** | 不含大规模买量 |

RTC 是最大的不确定变量。腾讯云公开后付费刊例价中，标清为 14 元/千分钟、高清为 28 元/千分钟，并按房间内订阅关系统计。按其公式粗算，2 人标清学习 60 分钟会产生约 120 订阅分钟，即约 1.68 元；4 人全互看 60 分钟约 720 订阅分钟，即约 10.08 元。实际账单受套餐、分辨率切换、订阅策略和优惠影响，因此必须限制免费额度、默认标清，并在产品埋点中记录“每场 RTC 毛成本”。[TRTC 定价与公式](https://buy.cloud.tencent.com/price/trtc)

## 11. 收入情景与盈亏平衡

以下是单位经济模型，不是收入承诺。假设订阅的折算月 ARPPU 为 15–16 元，另有少量主题包/B 端收入；获客费和渠道税费尚未计入。真正结果对留存、付费率和视频占比极其敏感。

| 情景 | MAU | DAU/MAU | 付费率 | 订阅月收入 | 其他收入 | 月总收入 | 月成本估计 | 结果 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| 保守验证 | 10,000 | 20% | 3% | 4,500 | 1,000 | 5,500 | 17,500–58,000 | 明显亏损，属于验证期 |
| 基准增长 | 50,000 | 25% | 4% | 30,000 | 10,000 | 40,000 | 51,000–157,000 | 多数情况下仍亏损 |
| 有效规模 | 200,000 | 30% | 5% | 160,000 | 50,000 | 210,000 | 152,000–475,000 | 只有成本受控时盈利 |

由此可见，单靠 18 元低价订阅很难覆盖高频多人视频。首个合理盈亏平衡目标不是某个固定 DAU，而是同时满足：

- 付费率达到 4%–6%；
- 付费用户折算月收入至少 15 元；
- RTC + AI 可变成本低于总收入的 25%；
- 自然增长和好友邀请承担主要获客，避免高额买量；
- 20% 以上活跃用户使用多人功能，但免费 RTC 有明确额度；
- 月固定团队与运营成本控制在 8–12 万元时，月收入需至少约 12–16 万元才有安全空间。

反推示例：若折算 ARPPU 为 16 元、付费率 5%、其他收入相当于订阅的 20%，每个 MAU 月均贡献约 `16 × 5% × 1.2 = 0.96 元`。要覆盖 12 万元总成本，约需 12.5 万 MAU；若视频使用使成本随用户显著增长，则实际需要更高规模或更高客单价。最重要的商业实验是测试“用户为陪伴和复盘付费”，而不是先预测宏观收入。

## 12. 路线图

### 阶段 0：两周产品验证

- 访谈 15–20 名目标用户，覆盖考研、考公、考证和在职学习。
- 用可点击原型验证开始目标、AI 介入频率、结束复盘和付费边界。
- 做 5–10 个固定好友小组的人工陪跑，验证邀请接受率。
- 成功门槛：至少 40% 受访者愿意连续使用一周；人工试验中每人一周完成 3 场以上。

### 阶段 1：第 1–4 周，单人闭环

- 登录、资料、目标、计时、两套场景、基础 AI、结束复盘、历史与埋点。
- 优先上线响应式 Web 内测；小程序同步完成登录和基础单人流程。
- 门槛：首场完成率 ≥ 60%，崩溃/阻断率 < 2%，AI 单场成本可观测。

### 阶段 2：第 5–8 周，好友共学

- 好友关系、邀请、2 人房再扩到 4 人、设备检测、弱网降级、举报拉黑。
- 增至五套场景，加入学习日历和周报。
- 门槛：邀请接受率 ≥ 25%，成功入房率 ≥ 95%，多人场完成率高于单人场至少 10 个百分点。

### 阶段 3：第 9–12 周，付费与公测

- 免费额度、Pro 权益、微信支付、退款与订单、成本告警、运营后台。
- 进行 500–2,000 人灰度，不做大规模投放。
- 门槛：D7 留存 ≥ 15%，周均完成 ≥ 3 场，试用到付费 ≥ 3%，RTC + AI 成本不超过收入的 35%。未达到时先优化留存，不扩 App 端。

### 阶段 4：验证后

- 只有在 D30 留存、自然邀请和付费成立后，再评估 React Native/Flutter 或原生 App。
- 先增加资料驱动的 AI 复盘和固定学习小组，再考虑陌生人匹配。
- 陌生人公开视频应作为独立项目重新评估审核团队、年龄体系和实时风控。

## 13. 测量体系

### 北极星指标

**每周完成目标的有效自习会话数（Weekly Completed Study Sessions）**。它比总时长更不容易被“挂机”误导，同时连接目标、坚持和复盘。

### 核心漏斗

`访问 → 登录 → 创建目标 → 成功开始 → 完成 ≥ 25 分钟 → 提交复盘 → 7 日内再次完成`

多人漏斗：`看到邀请入口 → 发出邀请 → 好友接受 → 双方成功入房 → 双方完成 → 再次同组`

必须同时观察：D1/D7/D30 留存、每周完成场次、目标完成率、好友邀请率与接受率、多人相对单人完成率、AI 使用后继续自习率、单场 AI 成本、单场 RTC 成本、举报率和封禁率。

## 14. 安全、隐私与合规

- 上线前确认经营主体、ICP 备案、微信小程序服务类目、隐私保护指引、用户协议和支付/退款规则；音视频类目与资质以微信审核结果为准。
- 最小化收集资料；城市只存到城市级且默认隐藏，性别为可选。摄像头与麦克风分别授权，并允许不用视频完成单人学习。
- 不录制视频、不做人脸识别、不推断情绪或专注度。AI 历史个性化需单独开关，支持删除和注销。
- 好友私密房仍必须有举报、拉黑、踢出、审计和紧急封禁。邀请令牌短时有效，不可被搜索引擎索引。
- 使用已完成相应备案/登记的国内模型服务，并对 AI 生成内容进行显式标识。2025 年发布的《人工智能生成合成内容标识办法》要求对生成合成内容实施标识，应在 UI 和导出内容中落实。[国家网信办说明](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)
- 若保留 16–17 岁用户，需要单独进行未成年人个人信息和视频风险评估。最省成本的 MVP 方案是先限制为 18+；年龄声明并非充分的年龄核验，扩大开放前应征询中国大陆专业法律意见。
- 白噪音、照片、视频循环和桌宠素材必须具有商业授权，保存来源、授权范围和到期日。

## 15. 测试与上线标准

- 单元测试：计时状态机、完成度、周统计、额度、邀请令牌和权限矩阵。
- 集成测试：微信登录、AI 超时/审核/降级、RTC 令牌、支付回调幂等。
- 端到端测试：Web 与小程序完成单人流程、2/4 人入房、断网重连、拒绝权限、提前退出和注销。
- 设备矩阵：至少覆盖主流 iOS/Android 微信版本、Chrome、Edge、Safari，以及低端 Android 真机。
- 压测：房间创建、心跳和总结队列按预计峰值 3 倍；RTC 媒体压力由供应商能力保证，但必须验证令牌和业务服务峰值。
- 上线阻断条件：成功入房率 < 95%、数据丢失、无预算上限、举报无法处理、摄像头在未明确授权时开启、AI 输出未标识。

## 16. 主要风险与应对

| 风险 | 概率/影响 | 应对 |
|---|---|---|
| 功能很多但留存不成立 | 高/高 | 单人闭环先行，每两周按指标砍功能 |
| 多人视频成本吞噬订阅 | 高/高 | 免费额度、标清、按需订阅、单场成本看板 |
| 小程序音视频审核或能力受限 | 中/高 | 第 1 周做技术 Spike 和审核咨询；Web 保底 |
| 没有好友可邀请 | 高/中 | 固定小组、一键再次邀请；不急着开放陌生人 |
| AI 变成干扰或通用聊天 | 中/高 | 规则触发、短回答、职责边界、用户可关闭 |
| 用户挂机导致指标虚高 | 高/中 | 北极星使用“完成目标会话”，时长仅作辅助 |
| 视频不当内容和隐私泄露 | 中/高 | 私密房、默认关闭、举报拉黑、不录像、18+ 优先 |
| 场景素材侵权 | 中/高 | 资产台账和商业授权，不抓取网络素材 |
| 供应商锁定 | 中/中 | RTC/AI 适配层；但 MVP 不做多供应商同时运行 |

## 17. Go / No-Go 决策

建议先批准两周验证和 8 周核心 MVP，不直接批准完整 12 周投入。第 8 周满足以下多数条件才继续支付和扩量：

- D7 留存达到 15% 或呈持续改善趋势；
- 每位活跃用户周均完成 3 场；
- 目标复盘提交率 ≥ 50%；
- 多人场完成率明显高于单人场；
- 至少 20% 活跃用户发起好友邀请；
- 用户访谈中能清楚表达“陪伴/监督”而非仅“白噪音”价值；
- AI + RTC 单场边际成本已可控，且存在至少 3% 的真实付费转化信号。

若留存成立但视频成本过高，保留好友文字状态/头像陪伴并把视频转为 Pro 权益；若单人留存成立而邀请弱，先做 AI 与固定学习小组；若只有白噪音受欢迎，则不应继续重资产建设社交平台。

## 18. 最终建议

这是一个值得做低成本验证、但不适合一开始重投入的项目。技术上没有不可实现的核心功能，真正难的是把陪伴感转化为长期留存，同时控制实时视频和 AI 的边际成本。

最佳切入点是：**一个让用户在 30 秒内设定目标并开始的桌面自习空间；AI 安静陪伴，好友可一键加入；结束后留下可信的目标复盘。** 先证明这个闭环每周被重复使用，再扩展 App、公开社区、资料学习和桌宠经济。

竞品的公开数据也支持这一判断：单点产品可以做大，但 DAU 和收益数据高度不透明；因此本项目不能以“竞品有百万用户”作为财务依据，而应以 2,000 人灰度中的留存、邀请、付费和单场成本决定是否继续。
