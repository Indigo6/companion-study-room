# 桌面端自动更新设计

## 目标与范围

为“伴读”Electron 桌面应用增加自动检查、下载和安装更新的能力，主要覆盖 Windows NSIS 与 macOS。更新包可来自公开 GitHub Releases 或自建 HTTPS 静态服务器。

Windows 在更新下载完成后提示用户选择“立即重启更新”或“稍后”，避免打断自习计时。项目当前没有 Apple Developer ID 证书，因此 macOS 第一阶段自动检查并下载 DMG，随后提示用户打开安装包手动覆盖；配置稳定签名与公证后，才启用应用内重启安装。

Linux 自动更新、预发布频道、灰度发布、后台静默强制安装和更新源运行时编辑不在本期范围。

## 技术方案

采用 `electron-updater`，沿用现有 `electron-builder` 打包体系。它原生支持项目使用的 Windows NSIS、macOS、GitHub provider 和 generic HTTPS provider，并可生成和消费更新元数据。

主进程新增 `update-manager.cjs`，使更新逻辑与窗口、AI 服务和设置存储解耦。该模块接收 updater、平台、应用状态与时间调度依赖，负责：

- 根据受信任的构建配置选择 GitHub 或 generic 更新源。
- 在已打包应用启动后延迟检查，并按固定周期继续检查。
- 防止检查或下载任务重入。
- 将 updater 事件转换为稳定、可测试的应用状态。
- 在 Windows 执行用户确认后的 `quitAndInstall()`。
- 在未签名 macOS 构建中定位并打开已下载的 DMG，不调用自动安装。

开发模式不连接真实更新源。测试通过注入模拟 updater 验证行为。

## 更新源与发布产物

更新源在构建或部署时确定，普通用户不能在界面中输入任意 URL。

GitHub Releases 使用 `github` provider，配置公开仓库的 owner 与 repo。自建服务器使用 `generic` provider，配置一个 HTTPS 基础 URL。两种发布方式使用相同版本号和 electron-builder 生成的文件格式，但每个应用构建只激活一个首选 provider；发布流程可把同一组构建产物同步到两个位置。

Windows 发布集合至少包含 NSIS 安装包、blockmap 和 `latest.yml`。macOS 同时生成 DMG 与 ZIP，以及 `latest-mac.yml`；ZIP 用于未来启用签名后的应用内更新，DMG 用于当前手动安装降级。

GitHub Actions 增加基于版本标签的发布路径，将安装包和元数据上传到 GitHub Release。自建服务器路径只负责生成完整产物并提供可上传的 Artifact，不假定具体服务器或云厂商凭据。

## 状态与交互

更新管理器对渲染进程暴露以下只读状态：

- `idle`：尚未检查或本轮结束。
- `checking`：正在查询更新。
- `available`：发现新版本，准备或正在开始下载。
- `downloading`：包含百分比、已传输字节和总字节。
- `downloaded`：安装包已就绪。
- `error`：包含面向用户的简短错误信息，保留当前应用可用性。

preload 只暴露检查、确认安装、打开 macOS 安装包和订阅状态变化所需的最小 IPC 接口。渲染进程不能直接访问文件系统、更新 URL、updater 对象或任意 shell 能力。主进程在发送状态前验证目标窗口仍然存在，并在订阅解除时清理监听器。

页面使用非阻塞提示展示更新状态。下载进行中显示进度；Windows 下载完成后显示“立即重启更新”和“稍后”；macOS 未签名构建显示“打开安装包”和“稍后”。用户选择稍后不会中断当前自习流程。

## 更新流程

1. 应用完成启动并创建窗口。
2. 更新管理器确认应用为打包版本、平台受支持且配置完整。
3. 延迟触发首次检查，避免阻塞首屏；之后按周期检查。
4. 发现更高的稳定版本后自动下载，持续上报进度。
5. Windows 下载完成后等待用户确认；确认后退出并安装，稍后则保持运行。
6. macOS 未签名构建下载 DMG 后等待用户确认；确认后使用系统能力打开 DMG，由用户手动完成覆盖安装。
7. 无更新或网络错误时结束本轮，保留下一次周期检查。

应用同一时刻只允许一次检查或下载。更新失败不能导致窗口关闭，也不能影响计时、摄像头、AI 请求或本地数据。

## 错误与安全处理

- 只允许 HTTPS generic 源；开发测试中的本地源由显式测试配置开启。
- 依赖 electron-builder 元数据中的哈希校验，拒绝损坏或不匹配的产物。
- 不把 GitHub token 或服务器凭据打入客户端；本期只支持公开或无需客户端认证的更新源。
- 将网络不可达、元数据无效、下载失败、平台不支持和安装调用失败映射为简洁状态，详细错误只写入主进程日志。
- 不自动降级，不默认安装预发布版本。
- macOS 未签名时禁止调用应用内自动安装，并明确提示手动安装。
- Windows 未配置代码签名仍可实现流程，但发布版本应尽快增加 Authenticode 签名，以降低系统警告并强化来源验证。

## 测试与验收

单元测试使用模拟 updater、窗口发送器、平台适配器和调度器，覆盖：

- GitHub 与 generic 配置选择，非法 generic URL 被拒绝。
- 开发环境、未打包环境和不支持平台不启动更新。
- 首次延迟检查、周期检查及重复检查抑制。
- updater 事件到公开状态的转换及下载进度规范化。
- 错误后恢复到可再次检查的状态。
- Windows 仅在下载完成且用户确认后调用安装。
- macOS 未签名模式只打开已下载 DMG，不调用自动安装。
- IPC 白名单、参数校验、订阅和清理。

渲染测试覆盖进度提示、平台对应操作按钮、稍后关闭提示和错误提示不阻断主界面。现有桌面与预览测试必须继续通过。

发布验收使用两个连续版本的已安装应用进行：分别从 GitHub Releases 和测试 HTTPS 静态目录检查并下载；Windows 验证提示后升级与版本变化；macOS 验证 DMG 被打开并可手动覆盖。签名与公证配置完成后，另行验收 macOS 应用内安装，再移除降级开关。

## 完成标准

- Windows 已安装版本能从任一受支持来源发现、下载新版，并在用户确认后重启安装。
- 未签名 macOS 已安装版本能发现、下载新版 DMG，并在用户确认后打开安装包。
- 更新状态和进度可见，用户可以选择稍后处理。
- 更新源故障不影响应用正常使用。
- CI 能为 GitHub Releases 和自建服务器生成完整且一致的更新产物。
- 自动化测试覆盖核心状态机、安全边界和平台分支，既有测试保持通过。
