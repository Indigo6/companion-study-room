# 陪伴自习室桌面 MVP 设计

> 日期：2026-07-14｜状态：已完成交互与架构评审，等待书面确认

## 1. 目标

构建一个 Windows 10/11 优先的单人陪伴自习 MVP。用户可选择沉浸背景和白噪音、运行番茄钟、与具有视觉形象的 AI 伙伴问答，并主动开启摄像头监督。第一版监督只判断“人在、离席、不确定”，不录制连续视频，不做人脸身份、表情、视线或注意力分析。

实施顺序固定为：先用 `frontend-design` 完成 Web 可交互视觉预览并交给用户审阅；视觉确认后接入实际功能框架；最后接入 Electron 桌面能力和 Windows 开发安装包。移动 App 不在本轮实现，但共享领域逻辑、API 类型和视觉令牌必须保持可复用。

## 2. 范围

### 2.1 MVP 包含

- Windows 10/11 桌面端，移动浏览器仅保证基本响应式预览。
- 雨夜书房、森林晨雾、海边黄昏、安静咖啡馆四套场景。
- 每套场景绑定默认白噪音，同时允许独立切换、调音量和静音。
- 25/5、45/10 和自定义番茄钟。
- 开始前填写目标；保存实际时长、暂停次数、离席次数和完成状态。
- AI 伙伴六种视觉状态：待机、专注、观察、思考、提醒、庆祝。
- 当前会话文本问答；默认短回答，防止问答取代学习。
- 用户主动授权的摄像头预览和低频抽帧监督。
- 演示 AI 模式，以及可替换的 OpenAI 兼容在线 API 适配层。
- 今日专注时长、最近记录、本地设置和一键清除问答。
- Windows 通知、最小化后计时和开发安装包。

### 2.2 MVP 不包含

- 账号、云同步、好友、多人房间和视频通话。
- 连续视频上传、录像、截图落盘和云端图片留存。
- 人脸身份识别、情绪识别、视线追踪或专注分。
- 看手机、趴睡等行为识别。
- 未配置 API 时伪装成真实 AI 判断。
- macOS/Linux 安装包、移动 App 安装包。

## 3. 核心交互

桌面主界面为单屏“自习桌”：全屏场景是空间主体，中央区域放置 AI 伙伴与番茄钟，下方为白噪音和监督状态，右侧抽屉承载 AI 问答，底部信息区显示本次目标和今日记录。

```text
┌─────────────────────────────────────────────────────┐
│ 场景切换                       今日专注  02:15       │
│                                                     │
│            动态学习背景 / 环境画面                  │
│                                                     │
│      ┌──────────────┐    ┌──────────────────┐       │
│      │   AI 伙伴    │    │   25:00          │       │
│      │  动画与状态  │    │ 开始 / 暂停 / 结束│       │
│      └──────────────┘    └──────────────────┘       │
│                                                     │
│ 白噪音：雨声 ━━━━━●━━   摄像头监督：已关闭          │
├──────────────────────────────┬──────────────────────┤
│ 本次目标与监督状态            │ AI 问答抽屉          │
└──────────────────────────────┴──────────────────────┘
```

### 3.1 场景与白噪音

场景背景优先使用前端原生 CSS/SVG 和轻量循环动画。预览阶段使用程序合成环境音，避免引入版权不明素材；正式素材必须记录商业授权来源。音频使用 Web Audio API，循环播放并在切换时淡入淡出。

### 3.2 番茄钟

状态机为 `idle → focus → paused/focus → break → completed`，也允许提前结束。计时使用绝对结束时间计算剩余时间，避免窗口失焦和系统调度造成累计误差。重启后保留历史，但不自动恢复运行中的计时或摄像头。

### 3.3 AI 伙伴与问答

AI 伙伴只在开始、离席、恢复就座和阶段结束时主动发言。问答默认限制长度。没有 API 配置时使用 `DemoAiProvider`，界面持续显示“演示模式”。真实接口统一为：

```ts
interface AiProvider {
  askQuestion(input: AskQuestionInput): Promise<AiAnswer>;
  inspectFrame(input: InspectFrameInput): Promise<PresenceResult>;
}

type PresenceResult = {
  status: 'present' | 'absent' | 'uncertain';
  confidence?: number;
  reason?: string;
};
```

在线模式支持 OpenAI 兼容的 `base URL + model name + API key`。开发者自带密钥由 Electron 主进程读取，不能进入渲染进程、日志或版本库。商业版本使用平台统一密钥时，必须经过远程后端代理，不能打包进客户端。

### 3.4 摄像头监督

监督必须由用户主动开启，界面持续显示工作状态。默认每 45 秒从本地视频抽取一张压缩帧；图片只用于一次判断，完成后释放，不写入磁盘、记录或问答历史。连续两次 `absent` 才触发离席；`uncertain` 不累计。关闭摄像头不影响番茄钟。

## 4. 技术架构

采用 Electron + React + TypeScript + Vite。Electron 使用 `contextIsolation`，渲染进程禁用 Node 权限，只暴露最小 IPC 白名单。Web 预览与 Electron 共用 UI、状态和领域代码。

```text
apps/
├── preview/              Web 预览入口
└── desktop/              Electron 主进程、预加载与打包
packages/
├── study-session/        番茄钟与会话状态机
├── ai-client/            Demo 与 OpenAI 兼容协议
├── supervision/          抽帧与离席判定
├── audio-scene/          背景与白噪音控制
├── storage/              本地设置和学习记录
└── ui/                   视觉令牌与 React 组件
```

主要依赖：

- React、TypeScript、Vite。
- Electron 与 Electron Builder。
- Zustand 管理界面状态。
- Vitest、React Testing Library 和 Playwright。
- Web Audio API、MediaDevices、Canvas。
- 本地 JSON/键值存储；本轮不引入 SQLite。

领域层不得依赖 Electron 或 React，以便未来复用于 React Native/Expo 移动端。移动端不承诺直接复用桌面 UI。

## 5. 数据流

### 5.1 监督流

`用户授权 → 本地视频预览 → 45 秒触发 → Canvas 压缩单帧 → AiProvider.inspectFrame → 结构校验 → 连续状态判定 → 伙伴提醒 → 释放图片引用`

真实 API 调用由 Electron 主进程或未来远程后端完成。预览阶段只能使用演示结果，并明确标识。

### 5.2 问答流

`用户问题 → 长度/状态校验 → IPC → AiProvider.askQuestion → 超时/错误归一化 → 短回答 → 当前会话显示`

问答默认不进入长期学习记录，用户可清空当前会话。

### 5.3 计时流

`目标 → 选择周期 → 开始 → 记录绝对结束时间 → UI 刷新 → 阶段完成 → Windows 通知 → 保存会话摘要`

窗口最小化不影响计时；系统休眠恢复后按实际时钟校正。

## 6. 错误与降级

- 摄像头拒绝：显示 Windows/浏览器开启方法，其他功能继续可用。
- 无摄像头：禁用监督入口，不阻塞自习。
- AI 超时、限流或断网：保留问题供重试；监督结果记为 `uncertain`。
- AI 返回非结构化结果：解析失败，不推断离席。
- 连续 `uncertain`：不提醒、不增加离席次数。
- 音频初始化失败：静默降级并提供重新初始化入口。
- 本地记录损坏：隔离损坏文件并恢复空状态，不能阻止软件启动。
- API 未配置：明确进入演示模式，绝不展示为真实判断。

## 7. 隐私与安全

- 摄像头默认关闭，权限目的在授权前说明。
- 不录制视频、不保存抽帧、不采集人脸身份。
- 页面持续显示监督开启状态、上次判断时间和当前模式。
- API Key 不进入渲染进程、日志、错误上报和 Git。
- Electron IPC 使用明确频道白名单并校验输入。
- 外部链接由系统浏览器打开；禁用任意页面导航和不可信脚本执行。
- AI 输出只能提供陪伴和学习辅助，不做健康诊断或高风险决策。

## 8. 测试与验收

### 8.1 自动测试

- 番茄钟所有状态转换、暂停、系统时间跳变和提前结束。
- 连续两次离席触发；一次离席或不确定不触发。
- 图片不进入持久化记录，不写入文件系统。
- API Key 不出现在渲染进程配置、日志或构建产物文本中。
- 摄像头拒绝、AI 离线和音频失败时主流程继续可用。
- AI 结构校验和错误归一化。
- Electron IPC 白名单、参数校验和窗口安全配置。
- 桌面、窄屏、键盘焦点和减少动画设置。

### 8.2 三个验收门

1. **视觉预览门**：先发布 Web 可交互预览，包含四套场景、AI 伙伴、番茄钟、声音控制、问答抽屉和模拟摄像头卡片。用户确认视觉与交互后才能进入下一阶段。
2. **功能框架门**：接入真实计时、合成音频、本地记录、摄像头权限和演示 AI。明确区分演示判断与真实 API 判断。
3. **桌面落地门**：接入 Electron IPC、后台计时、Windows 通知、设置存储和开发安装包；增加 OpenAI 兼容配置但默认不发真实请求。

## 9. Roadmap

- R1：识别看手机、趴睡和明显偏离学习区域。
- R2：经单独授权分析视线和注意力趋势，生成可解释的区间统计。
- R3：React Native/Expo 移动 App、账号与云同步。
- R4：好友邀请和 2–4 人共学。

R1/R2 不能通过简单扩展提示词直接上线。每个行为都必须有独立测试集、准确率与误报评估、敏感数据影响评估、明确授权、关闭入口和数据删除策略。注意力结果不得被表述为医学或心理结论。

## 10. 成功标准

- 用户能在 30 秒内选择场景、填写目标并开始专注。
- 无 API 配置时可完整演示四项核心能力，且模式标识无歧义。
- 开启监督后只上传低频单帧；关闭后立即停止抽帧。
- 摄像头和 AI 故障不影响番茄钟、背景和白噪音。
- Windows 最小化后计时准确并在阶段结束通知。
- Web 视觉预览须由用户确认后才进入 Electron 落地。
